# 现状评估与改进路线

本文只记录当前代码能支撑的工程判断，不保留旧外部调研和过期 commit 号。

## 当前优势

- WinPilot 采用混合感知：UIA、Win32、OCR、CV、可选 VLM。
- GUI 动作可带 expect 验证，done 还有二次核验，重点防假成功。
- 编程/仓库任务有独立 `CodingRunner`，避免主 GUI agent 工具过载。
- trace / `.wps.json` / Replayer / `wpsToFlowScript.ts` 形成“AI 首次操作 -> 可复用脚本”的闭环。

## 当前主要工程债

1. `agent/loop.py` 职责过多
   任务分类、done gate、上下文提示和反思检查点已拆出；LLM 调用、工具循环、上下文折叠仍在一个文件。

2. `agent/tools.py` 仍偏大
   schema、窗口、感知、输入动作、文件、记忆、桌面杂项工具已拆出；剩余主要是会话状态、dispatch、shell/launch/search/tray/plan/done/fail。

3. `python/engine/executor.py` 仍是巨型旧 DSLExecutor
   共享状态/上下文/异常已拆到 `executor_types.py`；主体仍应冻结为 legacy Flow/DSL 执行器，不继续扩张。

4. 文档和运行产物容易污染 AI 上下文
   已清理缓存/trace/截图，并补 `.gitignore`；后续继续减少重复文档。

5. 本机配置会影响测试
   `test_vision_priority.py` 已固定自身需要的 fusion 配置，避免 `config.json` 污染单测。

## 优先级路线

### P0：稳定边界

- WinPilot 新能力放 `python/winpilot_home/winpilot/`。
- Flow/DSL 新能力放 `src/renderer/`、`python/engine/`、`python/features/`。
- 两者通过 `.wps.json` / `wpsToFlowScript.ts` 桥接。

### P1：拆 WinPilot 核心大文件

建议先拆 `agent/loop.py`：

- `task_rules.py` 已完成
- `done_verifier.py` 已完成
- `context_guidance.py` 已完成
- `reflection.py` 已完成

再拆 `agent/tools.py`：

- `tool_schemas.py` 已完成
- `tool_result.py` 已完成
- `window_tools.py` 已完成
- `perception_tools.py` 已完成
- `interaction_tools.py` 已完成
- `file_tools.py` 已完成
- `memory_tools.py` 已完成
- `desktop_tools.py` 已完成
- `tool_session.py`

### P2：增强真实 GUI 评测

- 任务成功必须保存截图/trace/文件/进程/窗口证据。
- 可用 `scripts/gui_eval_run.py` 走 `/api/chat` 生成本机评测报告，避免 CLI 路径和前端路径不一致。
- 优先覆盖 UIA 不可靠软件。
- 不写单软件专属规则。

### P3：压缩上下文和工具噪音

- VLM/OCR/CV 输出必须是短结构化事实。
- 大结果必须折叠。
- 工具数量按任务模式动态收敛。
