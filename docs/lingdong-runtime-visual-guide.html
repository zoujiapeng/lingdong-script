02 · 完整流程图

一句话，怎样变成一次安全的电脑操作？

主线完整，最重要的异常分支也标在每一阶段下面。

1

先把人话变成可执行任务单

此时不会动鼠标

🔎识别意图做什么、对什么做
🧾生成任务合同阶段、能力、完成证据
🗺️生成 ARP 路线分支、重试、超时
能力缺失 → 鼠标没动就停止能力齐全 → 进入实时控制
↓
2

绑定正确窗口和当前画面

截图带有具体身份
🪟锁定目标窗口真实 hwnd，不偷用其他前台窗口
📸采集权威帧frame_id + 区域 + epoch
🎯圈出可操作区棋盘、画布或编辑区
👁️按需看懂界面真实像素优先，UIA/OCR/CV 补充
窗口找不到 / 被遮挡 / 表面不明确 → 不操作
↓
3

模型只决定一小轮，本地系统负责把关

模型不直接拥有物理鼠标
🧠只想当前一步谁的回合？点击还是拖动？
🧭找准落点和路径语义目标 → 当前像素
🛡️动作前再截图窗口和目标没变才继续
🔒封装动作单窗口、帧号、坐标来源、区域
窗口或目标变了 → 取消旧动作，重新观察语义有歧义 → blocked，不猜
↓
4

申请唯一鼠标/键盘，然后在本机执行

这一阶段才真正修改电脑
🚦桌面动作排队物理输入全局单写
🛡️每个子动作查窗口防止中途弹窗或焦点切换
⚡执行本地短事务点击、输入、拖动、等待
🖱️Windows 真执行UIA / SendInput / PostMessage
鼠标正被占用 → 等待，不争抢中途丢失焦点 → 清理输入状态并停止
↓
5

动作后重新看，有证据才算完成

API 返回成功不等于任务成功
📸拍结果画面新鲜 post-frame
🔍检查该变的区域来源、路径、目标和效果 ROI
🧾登记可追溯证据run、stage、provider、artifact
✅逐项验收全部义务满足才 done
📦保存成功经验导出 Automation IR 复用
动作无效果 / 结果不对 → 重新观察或恢复所有义务有当前证据 → 完成
03 · “合同”到底是什么

其实就是 6 张程序不能随便违反的单子

不是法律合同。点击卡片即可看懂各自管什么。

🧾Task Contract订单 + 验收清单
规定阶段、所需能力、工件和最终完成证据。
🗺️ARP Graph导航路线图
规定先后顺序、失败分支、重试、超时和结束路线。
🔒Action Envelope封口操作指令
写清针对哪个窗口、哪一帧、什么坐标来源和区域。
🧾Evidence Contract签收回执
写清证据证明什么、谁提供、是否 verified、属于哪个 run。
🔌Runtime Contract插头规格
保证 Electron 与 Python 协议、源码指纹和 Git 提交兼容。
📦Automation IR可复用菜谱包
保存步骤、条件、安全、证据和失败后的实时接管方式。
04 · 为什么不会轻易点错

四道门，任何一道不通过都不动手

原则不是“尽量猜对”，而是“无法证明安全时先停下”。

🪟窗口门

必须先明确目标 hwnd，不能偷用任意前台窗口。

📸新鲜帧门

动作前再截图；窗口、几何或目标像素变了，旧坐标作废。

🚦唯一输入门

真实鼠标键盘全局排队，两个任务不会同时抢光标。

✅证据完成门

输入发出不等于成功，必须看到正确结果。

点错窗口风险停止输入；尝试重新聚焦并连续确认身份。
窗口刚被移动旧坐标作废；取得新帧，不补偿猜测。
两个相似目标标记 blocked；不选“看起来最像”的继续点。
动作发出但没效果证据不通过；重新观察，不把 API ok 当成功。

最后只记住这一条链

你说目标→看当前画面→只想一小步→动作前再检查→本机真正执行→拿证据验收

核心不是“会点鼠标”，而是把每次操作绑定到正确窗口、正确帧、正确区域和可验证结果。
