# WinPilot 能力演示 · 怎么跑

这份演示把整个项目的两条能力线，在**同一台真机、同一个靶场**上一次性跑通，并用
**独立校验**（靶场自己写的 JSON 文件）判断每一步是真成功还是假成功。

- 第一部分：**离线编排**（canonical ARP）—— 一条流程在本地执行，**0 次模型调用**。
- 第二部分：**遗留 DSL 引擎** —— 图像/OCR/颜色/拖拽等传统自动化能力，同样离线。

> 关键点：Runtime 报 "done" 不算数，只有"Runtime 之外"的靶场 JSON 变了才算真成功。

---

## 一、先跑起来（一条命令）

在仓库根目录 `C:\Users\zou\Desktop\claude` 打开 PowerShell，执行：

```powershell
python-runtime\python.exe scripts\能力演示-一键运行.py
```

它会自动：① 启动 WinPilot 服务（若没启动）→ ② 打开一个演示靶场窗口 →
③ 依次跑第一部分和第二部分 → ④ 汇总结果 → ⑤ 关掉靶场。

跑完看这两处：

- 结果报告：`output\能力演示\第一部分-离线ARP报告.json`、`output\能力演示\第二部分-遗留DSL报告.json`
- **端到端矩阵**：`output\能力演示\端到端矩阵.md`（本次运行实测，逐项中文）
- 可视化流程：`python\winpilot_home\eval_targets\能力演示.flow`（可拖进 Electron Studio 打开）
- 完整节点说明：`docs\能力演示-端到端矩阵.md`

> 注意：运行时鼠标会被自动操作，请不要抢鼠标，等它跑完。全程约 1～2 分钟。

## 二、演示靶场长什么样

一个普通 Tk 窗口（标题 `能力演示靶场 | 演示`），上面摆了这些"可被操作的东西"，
每被操作一次就立刻把事实写进 `output\能力演示\靶场状态.json`：

| 靶场里的东西 | 用来演示什么 |
|---|---|
| 「点击我」按钮 | 单击点击是否点中 |
| 「文本输入」+「提交」 | 输入文字、提交 |
| 「悬停区」 | 鼠标移上去（悬停） |
| 颜色块（深蓝） | 颜色识别/校验 |
| 「开始进度」进度条 | 进度条等待（直到 100%） |
| 品红圆环星形图像 | 图像模板匹配点击 |
| 「OCR 文字」大号字 | OCR 文字识别 |
| 蓝框 → 绿框 拖拽区 | 拖拽/滑动 |
| 滚动区 | 滚轮滚动 |
| 「打开弹窗」 | 弹窗检测并关闭 |

这个靶场**完全不知道 WinPilot 的存在**，只是个普通窗口，所以它写出的 JSON 是"局外证据"。

## 三、第一部分：离线编排（canonical ARP）

**它在演示什么**：把一条"流程图"交给本机 Runtime 执行，走完全部可离线节点，
**不调用任何大模型**（省钱、可复现、可审计）。

这条流程图（`能力演示.flow`）依次经过这些节点：

1. **开始**
2. **动作批**：聚焦窗口 + 写剪贴板 + 等待
3. **设置变量**：`stage = armed`
4. **条件判断**：`stage == armed`？（是 → 继续；否 → 提前结束）
5. **离线重放·运行命令**：跑一条命令生成一个文件
6. **离线重放·写剪贴板**：再写一次剪贴板
7. **技能重放（未命中）**：查没有的技能 → 走"未命中"分支继续
8. **动作批（全部界面动作）**：单击、输入、提交、悬停、拖拽、滚轮、点击进度、点击图像、截图
9. **等待**：等进度条跑完
10. **证据门**：要求"必须有截图工件"才放行
11. **结束**

**结果怎么读**：报告里 16 项检查，每项都对照靶场 JSON，例如
"单击 = 1"、"输入并提交 = 演示文本-7391"、"拖拽 = 1"、"进度条 = 100"、
"截图工件 = 1"、"运行命令生成文件 = 已生成"；另有两项把握"离线"成色：
"模型调用次数 = 0" 与 "trace 完整"（接收 88 / 丢弃 0 / 写失败 0）。

> 演示会临时改写系统剪贴板，但**结束时会恢复你原本的剪贴板内容**。

## 四、第二部分：遗留 DSL 引擎

**它在演示什么**：用一段**中文可读的 DSL 脚本**（存成 `output\能力演示\演示脚本.dsl`），
在本地一次性执行，覆盖传统自动化能力，同样 0 模型调用。

脚本内容（就是报告里跑的那段）：

```
FOCUS 能力演示靶场 | 演示
SET stage armed
CLIPBOARD_SET 演示-剪贴板-<时间>
CLICK 477,113
IMAGE_FIND 演示图像 sim=0.85
IMAGE_CLICK 演示图像 sim=0.85
SCROLL -3
SWIPE <起点> <终点>
COLOR_CHECK <颜色块区域> 123456 60
IF ${_image_found}
  SCREENSHOT
END
LOOP 2
  IMAGE_FIND 演示图像 sim=0.85
END
POPUP_CLOSE 演示弹窗
```

每个指令在演示什么（通俗版）：

| 指令 | 通俗解释 |
|---|---|
| `FOCUS` | 把靶场窗口激活到最前 |
| `SET` | 设一个变量 |
| `CLIPBOARD_SET` | 把一段文字写进剪贴板 |
| `CLICK x,y` | 按坐标点一下 |
| `IMAGE_FIND 演示图像` | 用 OpenCV 模板匹配**在屏幕里找到那张图**（不管它在哪） |
| `IMAGE_CLICK 演示图像` | 找到那张图**并点它的中心**（图移了也能点对） |
| `SCROLL -3` | 滚轮向下滚 |
| `SWIPE x1 y1 x2 y2` | 从一点拖到另一点 |
| `COLOR_CHECK ... 123456` | 检查指定区域颜色是否为 `#123456` |
| `IF ${_image_found}` | 如果上一步找到图像了，就截图 |
| `LOOP 2 ... END` | 循环做两遍 |
| `POPUP_CLOSE 演示弹窗` | 找到标题含"演示弹窗"的窗口并关掉 |

**结果怎么读**：报告 8 项，全部对照靶场 JSON，例如
"图文点击 = 1"、"拖拽 = 1"、"关闭弹窗：开着=False 已关=1"。

## 五、这次顺手修好的三个真 bug

演示过程中发现并修复了三处真实缺陷（都已随代码生效）：

1. **缩放坐标落点偏移**（`python/interaction/actions.py`）
   遗留动作进程不是"DPI 感知"，Windows 会把物理坐标再缩放 1.25 倍，导致点击/拖拽
   落不到目标。现在进程启动即申请 DPI 感知，坐标与截图一致。

2. **中文路径读图失败**（`python/perception/vision.py`）
   OpenCV 的 `cv2.imread/imwrite` 不支持中文路径，模板名叫"演示图像"就找不到图。
   现在用 `numpy.fromfile + cv2.imdecode` 读取，中文文件名也能用。

3. **DSL 节点→能力桥接缺失**（`python/features/action_map.py`、`python/engine/executor.py`）
   - `IMAGE_FIND/OCR_FIND/REGION_WAIT/COLOR_CHECK/SCROLL/SWIPE` 的简写参数没有翻译成
     注册表功能的规范参数；现在补上了翻译，DSL 文本节点可正常执行。
   - `POPUP_CLOSE` 引用了早已删除的 `AutoPopup/ClickTarget`，永远返回失败；现在改用
     win32 按标题发 `WM_CLOSE` 关窗，并能关闭**自绘窗口**（不只是系统对话框）。
   - `POPUP_CLOSE` 还曾把自绘窗口的 `unhandlable` 误当"已处理"而提前返回，已修正。

## 六、已知边界（如实说明）

- `SWIPE` 对应的注册表功能 `swipe_action` 被标记为"废弃"，演示里改走底层动作实现；
  若你要长期使用，建议正式恢复它或统一到 `drag`。
- 演示里关闭了"每个动作后自动扫描弹窗"（`set_dialog_auto(False)`），否则在桌面上有
  多个窗口时会明显拖慢；这部分扫描逻辑本身偏激进，后续可优化。
- 第二部分的 DSL 里若**某一步失败，整条脚本会中断**（fail-fast）。这是引擎既有行为。

## 七、在前端（Electron Studio）里跑

前面是命令行跑。想在**前端界面**里跑同一个演示，按下面来：

### 第 1 步：启动前端

在仓库根目录 `C:\Users\zou\Desktop\claude`：

```powershell
npm run dev
```

（等价于 `vite` 起渲染进程 + `electron .` 起客户端；也可以直接双击/运行 `start-dev.ps1`。）
第一次会慢一点，等出现 Electron 窗口即可。前端会自动把本机 WinPilot 服务拉起来，无需手动起服务。

### 第 2 步：先打开演示靶场（关键）

这条流程用的是**真实屏幕坐标**，所以必须先把靶场摆到固定位置再跑：

```powershell
python-runtime\python.exe python\winpilot_home\eval_targets\能力演示靶场.py --state-file output\能力演示\靶场状态.json --case-id 前端演示
```

靶场固定出现在 `+60+40`，请保持它开着、不要移动、不要最小化。

### 第 3 步：在前端打开并运行流程

1. 在 Electron 里打开文件：`python\winpilot_home\eval_targets\能力演示.flow`
   （菜单“文件 → 打开”，或直接把 `.flow` 拖进画布）。
2. 点界面上的**运行工作流**按钮。
3. 观察靶场窗口“自己动起来”（被点击、输入、拖拽、滚轮、关弹窗…）。

### 第 4 步：看结果

- 前端会显示运行状态/节点高亮/日志。
- 独立校验还是看靶场写出的 `output\能力演示\靶场状态.json`：
  例如 `click_count`、`image_click_count`、`drag_count`、`popup_closed_count` 增长即为真成功。

### 说明与注意

- 前端运行**同一条流程**，同样是**0 模型调用**（这条流程没有 agent_goal 节点，纯离线）。
- 流程里的坐标是固定屏、`+60+40` 生成的；**换了分辨率/缩放或移动了靶场，坐标就会对不上**。
  要重新对齐，只需再跑一次命令行第一部分（它会重新生成 `.flow` 的坐标）。
- 若你想在界面上自己搭流程，可直接从节点库拖 `action_batch / condition / wait / replay_step /
  skill_replay / evidence_gate` 等节点（这些是前端可编译的节点）。
